How should the extension get the videos?

All three produce the same full-screen TikTok UI — this is about how we grab the video content

A

DOM Scraper Recommended

Content script watches X.com's DOM with MutationObserver. When video elements appear in the feed, the extension grabs their <video> src URLs and surrounding tweet metadata (author, likes, text). Builds the overlay from those.

Pros

  • No API key needed
  • Works with your login
  • Simple to implement

Cons

  • Breaks if X.com rewrites their DOM
  • Needs X.com to pre-load videos in DOM
B

Network Interceptor

Service worker intercepts X.com's internal API calls (api.twitter.com/graphql/VideoTimeline). Parses the JSON responses to get structured video data before it hits the DOM. More reliable data, but requires reverse-engineering X.com's private API.

Pros

  • Structured data, not fragile HTML
  • Gets data before DOM renders

Cons

  • Fragile to API schema changes
  • Complex to decode GraphQL responses
  • Potential ToS concerns
C

Scroll Hijack + Iframe

Overlay opens full-screen. Inside it, renders the actual X.com /i/videos page in a hidden iframe (or side panel). Extension then reads the iframe DOM and extracts the currently-playing video. Sidesteps needing to parse anything custom.

Pros

  • Doesn't need to parse X internals

Cons

  • X.com blocks iframes (X-Frame-Options)
  • Cross-origin restrictions
  • Very fragile

My recommendation

Approach A is the right call. X.com's video feed on /i/videos pre-loads video elements in the DOM before playing them. A MutationObserver on <video> elements is reliable, requires no external auth, and is fast to build. The main risk (X.com DOM changes) is manageable — the extension just needs to be updated when X changes their markup.
